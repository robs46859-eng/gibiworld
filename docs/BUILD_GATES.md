# GibiWorld — Build Gate Tracker

Engineering gates only. Every item here is discharged by writing code, wiring CI, or
producing an asset — nothing on this list is satisfied by a document or a sign-off.

reactive, owned elsewhere, and gating engineering on them produces false blockers. See
"Deliberately excluded" at the bottom for what moved out and where it went.

## B1 — Toolchain and reproducibility  `BLOCK`

Nothing downstream is trustworthy until local and CI build the same thing.

- `BLOCK` — **Unity `6000.0.74f1` not installed.** Machine has `6000.5.2f1`; CI pins
  `6000.0.74f1`. Local and CI currently disagree.
- `BLOCK` — **NSDK unresolvable without credentials.** Pinned to an immutable git tag;
  access is the only missing piece.
- `OPEN` — **No iOS XR provider entry.** `XRGeneralSettingsPerBuildTarget` covers Android
  and Standalone only; `NsdkARKitLoader` exists but is unassigned, so an iOS build would
  not start a session.
- `PASS` — Scenes generated by `SceneBuilder`, not hand-authored — diffable and regenerable.
- `PASS` — Package versions frozen in `manifest.json`; deviation requires an ADR.
- `PASS` — Android build intermediates untracked and gitignored.

**Exit:** one green CI build from a clean checkout on the pinned editor, for both platforms.

## B4 — AR runtime completeness  `PART`

The P0 loop works end to end. These are the gates it does not actually enforce yet.

- `OPEN` — **Hazard classes are unreachable.** `Sky`/`Person`/`Vehicle`/`Water`/`Road`/
  `Rail` are declared in `SemanticTag` but no code path emits them — ARCore plane
  classification doesn't produce them. §13.3's "no detected person/vehicle intersection"
  is **not enforced**. Needs semantic segmentation (Lightship, or ARKit people-occlusion
  stencil). Depends on B1/NSDK.
- `OPEN` — **`lightingConfidence` hardcoded to `1.0f`** in `ARSurfaceProbe`, so the 0.35
  gate can never fire.
- `OPEN` — **`clearanceHeightM` returns the spec minimum constant**, so the height gate
  never fires. Needs mesh-based headroom from `ARMeshManager`.
- `OPEN` — **VPS path untested.** `TargetSiteAnchor` is never assigned, so `usingVpsSite`
  is permanently false and three of six `AnchorEligibility` states are unexercised on
  device. Correct for P0; a risk carried into P1.
- `PART` — Depth occlusion wired (`AROcclusionManager`, `TrackableType.Depth` in raycasts);
  no mesh-based occlusion consumer.
- `PASS` — Six-state eligibility machine with 1.0 s dwell, 250 ms degrade, 3.0 s
  invalidation, 0.35 m pose-jump.
- `PASS` — Placement gates: motion, anchor state, camera start volume, hazard, slope,
  clearance radius — with purpose-dependent thresholds for pets vs. course objects.
- `PASS` — Status encoded as colour + icon + label + haptic; colour is never the only channel.

## Deliberately excluded

Not engineering gates. Tracked separately, handled reactively:

| Removed | Where it belongs |
|---|---|
| ADR-001 … ADR-010 acceptance | Spec change control |
| Legal review of guardian consent and care context | Legal |
| Threat model, privacy data-flow map | Security/privacy review |
| Accessibility conformance statement, caption audit | Compliance |
| SLO definitions, dashboards, runbooks | Ops |
| App-store privacy declarations, age ratings | Release/legal |
| Rigging, animation clips, prop scale | `docs/ASSET_PRODUCTION.md` |

The *code* behind several of these stays in scope — the age gate lives in B6, the
redaction and egress controls in B7, the four-channel accessible status encoding in B4.
What left is the paperwork, not the implementation.
